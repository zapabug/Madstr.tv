# feat-pwa-zapstore: an installable web app, and an Android app on zapstore

Branch: `feat/pwa-zapstore`, off `main`.
Status: spec from zapa's words on 2026-11-15 ("we need a service worker for the webapp, and zapstore
deploy"; Capacitor chosen over a TWA; zapa signs the zapstore release through a bunker).
Scope: the web app at madstr-tv.vercel.app becomes installable and opens offline; the same app ships as an
Android APK (phones and Android TV) published on zapstore.

## What zapa said (the source for everything below)

- A **service worker** for the web app.
- A **zapstore deploy**. Wrapper: **Capacitor** (the app bundled in the APK, WebView, works on TV boxes
  without Chrome), not a TWA.
- Signing: zapa signs the zapstore release through a **bunker** ("I just need to sign").

## Rules

- **No new runtime dependency** beyond Capacitor (OK'd by choosing it): `@capacitor/core`,
  `@capacitor/android`, and `@capacitor/cli` as a dev dependency, pinned exactly.
- **No secrets in the repo.** The APK release keystore and its passwords live outside the repo
  (`~/.android-keys/`, read by Gradle from `~/.gradle/gradle.properties`); zapa backs the keystore up.
  Losing it means zapstore cannot take updates. The bunker link is never written to the repo.
- The service worker **never caches** relay traffic, `/api/*` (RSS proxy) or media (audio, video, pictures):
  it only keeps the app's own files, so it can never serve a stale feed or eat storage with media.

## P1 — Service worker and web app manifest

- A hand-written service worker (`sw.js`, no library), generated at build time by a small plugin in
  `vite.config.ts` that lists the built files to keep (the app shell: `index.html`, JS / CSS bundles,
  fonts, icons). Its cache name carries the build's id, so a new deploy replaces the old files.
- Page loads (navigations): network first, the kept `index.html` when offline. The app's own files:
  from the cache. Everything else (relays, `/api/*`, media, other sites): not touched.
- A new version takes over on the next load (skip waiting, claim clients) and deletes the old cache.
- Registered only in production builds and not inside the Android app (the APK has the files already).
- `manifest.webmanifest`: name "Mad⚡tr.tv", short name "Madstr", start `/`, display `fullscreen`,
  colours `#0b0716`, icons 192 and 512 px PNG plus a 512 px maskable one, made from `favicon.svg`.
- Exit: the production build has `sw.js` and the manifest; with the network cut after one visit, the app
  still opens to the board; `/api/rss` and relay traffic never come from the cache; Chromium reports the
  app installable.

## P2 — Capacitor Android app (phone and TV)

- Capacitor added, `capacitor.config.ts`: app id **`com.madstr.tvapp`** (the id the first Madstr's
  Capacitor setup used; permanent once published — zapa to confirm), app name "Mad⚡tr.tv", web dir `dist`.
- `android/` generated by Capacitor and committed (minus build output). Android TV: a Leanback launcher
  entry and a 320×180 banner, touchscreen not required, so it shows on TV launchers and phones.
- The RSS proxy: inside the APK there is no `/api/rss`, so the app calls
  `https://madstr-tv.vercel.app/api/rss` when it runs in Capacitor (the same proxy the web uses).
- Known limit, not in this feat: audio stops when the app leaves the foreground (Android suspends a
  WebView; see snippet `capacitor-webview-audio-stops-in-background.md`). Fixing it needs a native player
  service — its own feat.
- Exit: `./gradlew assembleDebug` builds; the APK installs on an emulator or device and opens to the board.

## P3 — Signed release and zapstore

- A release keystore generated outside the repo; `assembleRelease` signs with it.
- zapstore publishing config in the repo (name, summary, repository, icon, the APK path); the publish is
  signed through zapa's bunker, approved on the phone.
- Open: which identity publishes (zapa `npub18weq…` as on pleb.world, or `d83b5ef1…` TugaJoe), and a
  bunker connection made for zapstore (not reusing another app's session).
- Exit: a signed release APK; the zapstore release event published and the app visible on zapstore.
